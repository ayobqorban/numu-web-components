# Contributing

Read `AGENTS.md` and the required architecture documents first. Work on a feature branch, keep changes focused, and preserve existing public contracts.

Before opening a pull request:

- complete `COMPONENT_DEVELOPMENT_CHECKLIST.md` when applicable;
- update the registry, tests, catalog, documentation, and changelog;
- run lint, typecheck, tests, and build;
- inspect `git status` and the diff for secrets, generated clutter, and unrelated changes.

Commit messages use a conventional form such as `docs: establish standards`, `feat: add versioned block registry`, or `test: cover invalid block data`.
