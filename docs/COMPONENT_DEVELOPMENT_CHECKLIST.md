# Component development checklist

- [ ] An equivalent component does not already exist.
- [ ] A stable block key and schema version are selected.
- [ ] Props type is added without unjustified public `any`.
- [ ] Strict runtime schema is added.
- [ ] Preview-safe defaults pass the schema.
- [ ] Registry definition and localized metadata are added.
- [ ] Only semantic theme tokens are used.
- [ ] RTL and LTR are verified.
- [ ] Mobile, tablet, desktop, and wide desktop are verified.
- [ ] Accessibility and keyboard behavior are checked.
- [ ] Server/client boundary is reviewed.
- [ ] No business logic, consumer state, or direct API calls are present.
- [ ] Unit and accessibility tests are added.
- [ ] Catalog examples are added.
- [ ] Registry documentation and changelog are updated.
- [ ] Lint, typecheck, tests, and build pass.
